# CLAUDE.md — Правила для агентов KremnevAtelier

Этот файл читается всеми агентами Claude Code при старте. Следуй правилам строго.

---

## 1. Регистрация задачи (ОБЯЗАТЕЛЬНО)

**Перед началом любой работы** создай файл задачи:

```
.agents/tasks/<твой-идентификатор>.md
```

Идентификатор — короткое описание задачи в kebab-case, например:
`fix-footer-links.md`, `update-hero-section.md`, `refactor-about-team.md`

**Шаблон файла:**

```md
# Задача: <описание>

**Агент:** Claude Code (сессия начата: YYYY-MM-DD HH:MM)
**Статус:** in-progress | done | blocked

## Что делаю
- Краткое описание изменений

## Файлы, которые изменяю
- src/components/sections/Footer.tsx
- src/content/pages/home.ts

## Не трогать другим агентам
- (список файлов, если нужна изоляция)
```

**По завершении задачи** удали файл или смени статус на `done`.

---

## 2. Проверка перед стартом

Перед началом работы выполни:

```bash
ls .agents/tasks/
```

Если там есть активные файлы (`in-progress`) — прочитай их. Если другой агент работает с теми же файлами — дождись завершения или работай в других файлах.

---

## 3. Деплой

**Никогда не запускай `npm run build` или `./scripts/deploy.sh` напрямую** без явной просьбы пользователя.

Деплой защищён flock-блокировкой. Если деплой уже идёт — скрипт завершится с ошибкой. Не пытайся запускать его повторно.

```bash
./scripts/deploy.sh   # единственный способ деплоить
```

---

## 4. Git

- Не делай `git push` без явного запроса пользователя.
- Не делай `git commit --amend` если не просят.
- Не используй `--force` push.
- **Каждый участник команды работает в своей ветке.** Не коммить и не пуши в чужую ветку. `main` — только для мержа готового кода.
- **Агенты Claude Code работают только в ветке `kit`.** После завершения задачи — запушить изменения и создать Pull Request в `main`.

## 5. Правила хранения контента (ОБЯЗАТЕЛЬНО)

**Все пользовательские тексты — в контент-файлах, не в TSX.**

Контент-файлы: `src/content/pages/*.ts`

### В TSX допустимо хранить:
- JSX-разметку: теги, атрибуты, `className`, `style`, `href` (не меняющиеся)
- Логику компонентов: `useState`, `useEffect`, обработчики событий
- `aria-label`, технические строки (имена CSS-классов, SVG `d`-атрибуты)

### В TSX запрещено хранить:
- Заголовки, подзаголовки, тело текста, лейблы кнопок, placeholders
- Любую строку, видимую пользователю на экране

### Правило для `EditableText`:
```tsx
// ✅ правильно — children берётся из контент-файла
<EditableText id="dev.hero.title">{c.hero.title}</EditableText>

// ❌ неправильно — строковый литерал в JSX
<EditableText id="dev.hero.title">Заголовок страницы</EditableText>
```

Если `EditableText` получает строковый литерал как `children` — API не найдёт куда сохранять правки из дебаг-режима. Правки потеряются.

### При добавлении нового текста на страницу:
1. Сначала добавь строку в `src/content/pages/<page>.ts`
2. Импортируй контент в `page.tsx`: `import { pageName as c } from "@/content/pages/..."`
3. Передай в компонент через пропс или напрямую: `{c.section.field}`

## 6. Дебаг-направляющие (сетка)

В дебаг-режиме (`?debug=1`) отображаются вертикальные направляющие — компонент `src/components/ui/DebugGuides.tsx`.

| Направляющая | Позиция | Описание |
|---|---|---|
| A1 | `(100vw − 1920) / 2` | Левый край контента (max-width 1920) |
| A2 | симметрично A1 справа | Правый край контента |
| A3 | A1 + 80px | Левый внутренний отступ (padding 80px) |
| A4 | A2 + 80px внутрь | Правый внутренний отступ |
| A5 | A1 + 40px | Левый блочный отступ (padding 40px) |
| A6 | A2 + 40px внутрь | Правый блочный отступ |
| **A7** | **580px от левого края** | **Основной разделитель колонок** |
| A8 | A4 − 500px | Направляющая для правой части |
| A9 | 820px | Дополнительная |
| A10 | 1105px | Дополнительная |

**При вёрстке двухколоночных секций** используй направляющие для выравнивания. Например, если правая колонка должна начинаться от A7 (580px), учитывай padding секции: `580 − padding = ширина левой колонки`.

## 7. Стек и конвенции

- **Framework:** Next.js 16, App Router
- **Стили:** Tailwind CSS 4
- **Типизация:** TypeScript (строгий режим)
- **Контент:** хардкод в `src/content/` — нет CMS, нет базы
- **Алиасы:** `@/*` → `src/*`
- **Dev-порт:** 3010 (`npm run dev`)
